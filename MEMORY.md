# Memory — Long-Term

Stable project knowledge. **Read at session start.** Rules: `agent_docs/memory_process.md`.

Only what has no other guard lives here. A gotcha whose fix a `selftest` check locks in, or whose rule an on-demand doc already carries, sits in `agent_docs/memory_archive/` — see _Archive_ at the bottom and **grep there before re-deriving anything.**

## Architecture Decisions

Structured decisions live in `docs/adr/`. Grep there before contradicting one, and reverse one only with a new ADR that supersedes it — never by editing the accepted one.

- **ADR-0005** — merging and releasing need an explicit user command, but an owner-authorized routine counts as one (non-destructive change sets with green verification only). Supersedes ADR-0004. (#21)
- **ADR-0006** — `insecure_ssl` covers every connection, the updater's exe download included. Supersedes ADR-0002. **Don't re-add a `verify=True` to `updater.py`.** (#20)
- **ADR-0007** — PySide6 (Qt 6) is the UI toolkit, and the app's one large dependency. Back-filled 2026-08-17.
- **ADR-0008** — transcription stays fully local; the network is touched only by the model download, the opt-in assistant and the updater. Back-filled 2026-08-17.
- **ADR-0009** — system audio is captured through an OS-provided loopback/monitor **input** device, never a WASAPI loopback stream; no candidate = **refuse the take**, never fall back to the default input (that is a microphone). (#191, open alternatives in #192)

## Gotchas & Pitfalls

- **`--windowed` builds have `sys.stdout`/`sys.stderr` = None.** Any library that writes to them crashes — huggingface_hub's tqdm progress bar killed the OpenVINO model download with `'NoneType' object has no attribute 'write'`. `app._ensure_std_streams()` stubs them with devnull right after logging setup; keep that call early in `main()`. (2026-07-20)
- **Desktop coordinates cannot remember which monitor a window was on.** The floating icon's saved position kept landing on the main screen after every reboot: at logon the app is up before Windows has finished bringing up the secondary displays, the saved spot is then on no screen, and the fallback to the primary was permanent because nothing looked again. Fixed by anchoring the position to a monitor identity (`overlay.screen` = EDID manufacturer|model|serial, else the device name — never the desktop coordinates, which move on every rearrange/resolution/primary change) plus `overlay.rel_x/rel_y` inside it, a bounded retry while that monitor is still missing, and re-applying the saved position on _every_ screen-topology change (Windows moves windows off a monitor that goes away — a DisplayPort screen dropping out on standby is enough — and never moves them back). Keep all three: any one alone leaves a case broken. (2026-08-13)
- **The backend and the model preset are one choice, not two.** The OpenVINO organisation publishes IR conversions for `whisper-{tiny,base,small,medium,large-v3,large-v3-turbo}{,.en}` and `distil-whisper-large-v3` — and for nothing else in `MODEL_CHOICES`. Four presets (the German turbo CT2 fine-tune, `distil-large-v3.5`, `distil-small.en`, `distil-medium.en`) therefore cannot run on that backend, and the pairing used to be accepted by every screen and refused only by the first transcription, i.e. after the user had already spoken. `choices.OPENVINO_UNSUPPORTED_MODELS` is the single source of truth: it maps each to a working replacement, `models_for_backend()` filters both dropdowns, and `transcriber_openvino` raises from the same map. When adding a model preset, decide its OpenVINO status there — a new preset defaults to "supported" and would 404 on download. (#112, 2026-08-17)
- **The overlay watchdog must not trust any single visibility signal.** The icon kept vanishing with the 30 s watchdog running (user report 2026-08-19): `isVisible()` only reports the _requested_ Qt state, `raise_()` never re-applies a stripped `WS_EX_TOPMOST` (explorer restarts strip it from every topmost window), and a pure resolution change fires no screenAdded/Removed/primaryScreenChanged at all — a stranded icon was repaired by nothing. The watchdog now probes every 5 s (Qt state, on-a-screen, win32: expose state / `IsWindowVisible` / DWM cloaking), repairs on a throttled ladder (hard re-show → one native-window rebuild → ~30 s retries; a probe that is wrong on some setup must never hide()/show() at 5 s), re-asserts `HWND_TOPMOST | SWP_SHOWWINDOW` natively every tick (idempotent, no flicker), and watches `QScreen.geometryChanged` too. Every repair logs which probe fired — that log line is how the real drop mode gets identified. **The user's own reading is that the icon is not gone at all, only buried** (2026-08-20), so a `WS_EX_TOPMOST` probe was added and the z-order case is repaired in place (SetWindowPos, never hide()/show() — a buried window needs no rebuild, and the flicker would be pure cost). Whether the icon is forced on top is now the explicit `overlay.always_on_top` setting: when it is off, nothing may force the icon over the user's windows — that is what they asked for. **A green `check` job proves nothing about the win32 probes**: they sit behind `sys.platform != "win32"`, so the Linux CI run returns before reaching them and only the release build's `--selftest` on the exe runs them — that is where the first version failed. `isExposed()` is false right after every `show()` until the platform has painted the window, so it needs a tick of grace or every repair reports itself as failed; the selftest now fakes `sys.platform`/`windowHandle` to exercise that branch on any platform. (2026-08-19, extended 2026-08-20)
- **Hold mode and a synthesized mute tap don't mix when they share keys.** In hold mode the recording hotkey is physically down while the "start" tap of a toggle mute target goes out. If the target's keybind shares a key with the hotkey, the tap's synthetic release reaches `Hotkeys._handle_release` and ends the recording; if it carries a modifier, the chord goes out widened by the held keys and misses the target. `integrations._hold_mode_skip_reason` therefore skips such a target for that take and notifies once per session — a silent no-op here would look like "mute doesn't work". Hold-mode _targets_ are never gated (they release only after the take). Toggle-mode recording is unaffected: `injector.wait_for_quiet_modifiers` waits for the hotkey to be released first. The full fix (filter `LLKHF_INJECTED` events in the hotkey hook, release/re-press held modifiers around the tap) is sketched next to the guard. (2026-09-06)
- **sounddevice declares `PaWasapi_IsLoopback`; the PortAudio it ships does not export it.** The trap is the contradiction, not the absence: sounddevice's own CFFI declarations _do_ declare `PaWasapi_IsLoopback`, so the API reads as one `_lib` call away — but the binary in its Windows wheel (>=0.5.6) is `PortAudio V19.7.0-devel`, which exports 13 `PaWasapi_*` symbols and not that one, and holds no `[Loopback]` device-name string in either ASCII or UTF-16 (same for the `-asio` and `arm64` builds). `WasapiSettings(exclusive, auto_convert, explicit_sample_format)` is the whole WASAPI surface offered; "loopback" appears nowhere in `sounddevice.py`. So no WASAPI loopback stream can be opened from this stack — don't "fix" the capture path by reaching for a flag that is not in the binary; it goes through a loopback/monitor **input** device instead (ADR-0009). Re-measure before assuming it still holds — artifact `sounddevice-0.5.6-py3-none-win_amd64.whl` from `pip download sounddevice --no-deps --only-binary :all: --platform win_amd64 --python-version 3.12` (DLL path inside the wheel and the dump commands: ADR-0009), and `requirements.txt` has no ceiling on `>=0.5.6`, so pip resolves past the measured version: the declaration means upstream has it, so a newer wheel makes it real, and it would then also enumerate every output a second time as `<name> [Loopback]`, which `system_audio.LOOPBACK_HINTS` already scores highest. Alternatives tracked in #192. (#191, 2026-09-10)
- **`SO_REUSEADDR` does not mean the same thing on Windows as on POSIX — never set it "for both".** On POSIX it only relaxes a lingering `TIME_WAIT` entry; two live listeners on one address still collide (that would need `SO_REUSEPORT`). On Windows the same option is the permissive one: it lets an unrelated process bind a port we are already listening on and take the connections over. The Windows equivalent of "mine alone" is `SO_EXCLUSIVEADDRUSE`, which is what `singleinstance._set_address_reuse` sets there. Worth keeping straight because this repo is Windows-first, and because the naming invites exactly the wrong copy-paste. Note it is _not_ what makes the app single-instance: that guard is the named mutex (Windows) / `flock()`ed file (POSIX) in `acquire()`, and the socket is only the "show yourself" ping channel — so a bind that fails degrades the ping, never the guard. (#130, 2026-08-25)
- **A predictable path in the shared temp dir is somebody else's to claim.** `theme._asset_dir` used to fall back to `<system temp>/listen-to-me`; on a multi-user host any account can create that first, and `mkdir(exist_ok=True)` then accepts a foreign directory — or a symlink into one — without a word, while everything written there is read back through a QSS `url()`. The fallback is now `config_dir()/cache`, and `theme._own_dir` refuses a symlink or a foreign owner and chmods 0700 on POSIX. Same rule anywhere else this comes up: user-owned directory or `tempfile.mkdtemp()`, never a guessable name under the shared root. (#130, 2026-08-25)
- **A factory reset is an App operation, not a settings-window one.** Half of what "back to defaults" means lives outside `config.json`: the global hotkey has to be re-registered, the OS autostart entry actually removed, the transcriber rebuilt for the default backend, the floating icon placed where a fresh install puts it. So Settings only confirms and posts `factory_reset`; `App._factory_reset` resets the config, calls `apply_settings()` and only _then_ runs the wizard — the order matters, because the wizard can be cancelled and what keeps running must be the reset app, not the configuration the user just discarded. The icon uses `Overlay.reapply_position()` (re-reads the config), never `reset_position()` — that one _saves_, which would write coordinates into a config that is supposed to be factory-clean. `_resetting` guards the wizard's nested event loop against a second reset being drained into it. (#111, 2026-08-17)

- **OpenVINO GPU/NPU compile the model on every load unless `CACHE_DIR` is set.** `WhisperPipeline(path, device, **properties)` takes OpenVINO properties; without `CACHE_DIR` an NPU load of a large model takes minutes _every start_ (openvino.genai#1992: minutes → seconds with it). `transcriber_openvino._pipeline_properties` sets it for GPU/NPU under `config_dir()/cache/openvino-cache` (or the custom model folder) and never for the CPU, whose blob would only cost disk. A plugin that rejects the property gets one bare retry before the failure may count as "device unusable". Since CTranslate2 4.6.3 the Windows/Linux wheels are built without cuDNN (`WITH_CUDNN=OFF`) — the GPU path needs cuBLAS 12 only; and onnxruntime-gpu ≥ 1.27 targets CUDA 13 while CTranslate2 stays on CUDA 12, so the two NVIDIA backends can need two different CUDA runtimes side by side. (#168, 2026-09-06)

## External Dependencies

- **faster-whisper / CTranslate2** — models download from Hugging Face on first use into the HF hub cache (or `model_dir`); later loads are offline (`local_files_only`). GPU needs the NVIDIA CUDA 12 libraries or it falls back to CPU. (2026-07-19)
- **pynput** — global hotkey + synthetic keypress behavior differs per OS (X11 auto-repeat, macOS/Windows send no release on hold). Imported lazily; needs an X display on Linux only when actually used. Two traps that cost real debugging — the 1.8 `HotKey.parse` change and Shift-uppercasing turning a synthetic chord into text — are in the 2026-08 archive; read it before touching `keymap.py` or `integrations.py`. (2026-07-19)
- **sounddevice / PortAudio** — mono float32 @ 16 kHz (what Whisper expects); device index from settings, `None` = system default. A loopback/monitor input usually refuses that format, so `Recorder` opens it at the device's own rate and converts in the callback — **what the recorder stores is 16 kHz mono whatever the stream ran at** (`Recorder.resampling` says whether it converted; `stream_format` reports the stream, not the buffers). PortAudio itself never resamples. (2026-07-19, extended 2026-09-10)

## User Preferences

- **No new tooling without approval** — there is intentionally no linter/formatter/type-checker/test-framework. Don't add ruff/black/mypy/pytest to make a check pass; match style by hand. (2026-07-19)
- **Windows-first**, Linux/macOS paths kept coherent. (2026-07-19)
- **Every agent-config rule is stated in exactly one place; the others point at it.** Three that were pruned back and should not be rebuilt: reviews run **on demand** via the `review` skill — don't re-add "every implementation triggers a review" to `agent_docs/review_process.md`; Dependabot PRs route like any other PR — don't re-add a separate dep-bot PR workflow to the `pr` skill, `/pr merge` already covers them; the `gh` → `mcp__github__*` fallback is stated once in `agent_docs/mcp_catalog.md` — skills link to it instead of each restating a different variant. (2026-08-02)
- **`permissions.allow` holds one `mcp__<server>__*` glob per spelling and nothing a glob already covers.** 16 redundant per-tool entries were pruned on 2026-08-02; they granted nothing the globs didn't. Self-heal by _appending_ a missing glob, never per-tool names, and never a `deny`/`ask` entry. The two `mcp__github__(un)subscribe_pr_activity` entries stay only because there is deliberately no `mcp__github__*` glob. (2026-08-02)
