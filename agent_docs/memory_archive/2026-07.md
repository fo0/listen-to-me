Most of these are Qt/Windows UI traps whose fix is already locked in by a `selftest.gui_smoke` check, plus the history behind the current autostart and single-instance designs. They matter when you touch those areas; they do not need to be in every session's context.

## Gotchas & Pitfalls

- **Hold-mode hotkeys can miss the release** (WM/IME grabs, focus change); recording still stops via the overlay/tray Stop entry or the max-length auto-stop. X11 auto-repeat needs the release debounce in `hotkeys.py`. (2026-07-19)
- **Relaunching the frozen exe needs a reset environment.** Since PyInstaller 6.9 a spawned copy of the one-file exe is treated as a worker subprocess that reuses the parent's `_MEI` unpack dir — which is deleted when the old process exits. The updater's restart chain (cmd → batch → new exe) inherited those variables, so the freshly updated app died on startup with a Python-DLL/module error while a manual start of the same exe worked. Any in-app (re)launch of the exe must go through `updater._swap_env()`: strips `_MEIPASS2`/`_PYI_*`, sets `PYINSTALLER_RESET_ENVIRONMENT=1`. (2026-07-21)
- **A TCP-port bind is not a reliable single-instance lock on Windows.** Hyper-V/WSL "administered port exclusions" (`netsh int ipv4 show excludedportrange`) can make `bind()` on a fixed port fail although nothing is running (the app then silently refused to start) or *succeed in several processes at once* (multiple instances ran side by side). `singleinstance.py` therefore claims a named kernel mutex on Windows / an `flock`-ed file on POSIX; port 52697 only carries the "show yourself" ping from a second launch. (2026-07-23)
- **Windows drops the overlay window without Qt noticing.** Display sleep / DWM restarts hide layered (`WA_TranslucentBackground`) windows, explorer restarts and fullscreen apps eat `WindowStaysOnTopHint`, monitor changes can strand the position off-screen — while `isVisible()` stays `True`, so a plain `show()` no-ops. The Overlay watchdog re-asserts every 30 s (`raise_()`, `show()` if Qt-hidden) and hard-reshows (`hide()`/`show()`) after a suspend (timer-gap heuristic) or screen add/remove/primary-change signals. (2026-07-23)
- **A QComboBox's minimum width grows with its longest item — and QScrollArea honors it.** One over-long entry (the German-turbo preset label, a custom HF model id, an audio device name) forces the whole settings page wider than the viewport; with the horizontal scroll bar off, every card is then silently clipped at the right edge. Wrap such combos with `qtutil.elastic_combo` (AdjustToMinimumContentsLengthWithIcon + Expanding); the gui_smoke selftest asserts no page is wider than its viewport. (2026-07-23) — **A wrapping `QLabel` does the same thing**: word wrap only breaks at spaces, so a single long "word" (a Windows program path, an audio device id) still sets the minimum width — 547 px for a realistic exe path. Keep raw paths out of status lines (`autostart.short_command` shows the file name, the full command goes into the tooltip). (2026-07-30)
- **Settings dropdowns must be read-only — never `setEditable(True)`.** The model combo was editable so users could type a custom CT2 model id; any accidental keystrokes were then saved verbatim as the model id and failed only at model load. Unlisted values go through an explicit sentinel entry + input dialog instead (`CUSTOM_MODEL_LABEL` in choices.py, resolved in `settings_ui._on_model_activated`, never stored as a value). Free-text fields are OK only when save-time validation rejects bad input loudly (hotkey → `Hotkeys.validate`). (2026-07-23)
- **History/config values are untrusted at render time — and Home renders during window construction.** `float(when)` raises TypeError on a non-numeric JSON value and `time.localtime()` OverflowError on an out-of-range one; with the Home page built inside `SettingsWindow.__init__`, an uncaught error there makes the whole main window (and the tray's Settings/Updates/Help entries) unopenable, not just one page. Catch `(TypeError, ValueError, OverflowError, OSError)` when formatting stored timestamps; gui_smoke keeps a `1e300` history entry as a regression guard. (2026-07-25)
- **Rebuilding a layout twice in one event-loop pass leaves ghost widgets.** `deleteLater` keeps the widget parented and painting until the event loop processes the deletion; a replaced-but-never-laid-out widget even paints at the default 640×480 geometry (this drew a stray border line across the Home hero). When clearing a dynamic layout, detach first: `widget.hide(); widget.setParent(None); widget.deleteLater()` — see `HomePage._clear_layout` and `SettingsWindow._clear_history_rows`. `layout.takeAt()` alone is **not** enough: it unmanages the widget but leaves it parented, so it keeps painting. gui_smoke asserts the replaced History rows end up parentless. (2026-07-26)
- **A non-dict stored value must never replace a nested config section.** `config._merge` used to copy any stored value verbatim, so `"overlay": null` (hand-edited, truncated write, older build) wiped the whole defaults subtree — and the first access, `Tray.start()`'s `cfg["overlay"]["enabled"]`, raised *before* any window or tray existed. The app then simply didn't start, with nothing but a log line. `_merge` now keeps the defaults (with a warning) whenever the default is a dict and the stored value isn't. Treat the config file exactly like history.json: untrusted input. (2026-07-26)
- **Pixmaps painted in code don't follow a live OS theme switch.** `theme._refresh` re-applies the palette + QSS on `colorSchemeChanged`, but a `QIcon`/`QPixmap` built from `tokens()` keeps the colours it was created with — the nav glyphs, Home quick actions and the Help browser's *baked* default style sheet stayed in the old scheme until the window was reopened. `SettingsWindow._on_color_scheme_changed` rebuilds them (`HomePage.restyle_icons`, `_render_help` — a `QTextDocument` bakes its default style sheet into the rendered HTML, so re-setting the sheet needs the HTML set again). Anything new that reads `tokens()` outside the QSS belongs in that handler. (2026-07-26)
- **A `QDialog` used as the app's main window has no minimize/maximize box.** Qt gives dialogs only a close button, so the (resizable, scrolling) main window couldn't be sent to the taskbar. `setWindowFlag(WindowMinimizeButtonHint/WindowMaximizeButtonHint, True)` fixes it without losing `Qt.Dialog` semantics (Esc/reject, the unsaved-changes prompt). (2026-07-26)
- **The first-run wizard's key picker runs while the global hotkey is already live.** `App.run()` registers the hotkey *before* it shows the onboarding wizard, so pressing the current combination in the picker started a real recording behind the modal wizard — on the very first launch. Both pickers now pause `app.hotkeys` and call `app._register_hotkey()` in a `finally` (`OnboardingWizard._capture_hotkey`, `settings_ui._capture_hotkey`). Any future dialog that reads raw key presses needs the same pause. (2026-07-26)
- **An autostart entry stores a path, and "enabled" said nothing about that path.** `autostart.is_enabled()` only checked whether the `Run` value / plist / `.desktop` file *existed*, so `sync()` was a no-op once the registered exe had moved: after a **manual** update (new exe with the dated release name, or a rename/move) Windows booted the old build — or nothing — while Settings still showed the option ticked. `sync()` now also compares the stored command with `_launch_args()` and rewrites it when the target is gone or another frozen build is registered (`stored_command()` + `_refresh_reason`). Deliberately *not* rewritten: a launch of a different kind whose target still exists, so a source checkout can't hijack an installed build's entry. The **in-app** updater never needed this — `_swap_script` moves the download onto the running exe's own path, so the name on disk never changes; the dated `ListenToMe-<date>-<time>-win64.exe` is only the GitHub asset name. (2026-07-27)
- **Windows keeps a second on/off switch for autostart entries.** `Task Manager → Startup apps` (and `Windows Settings → Apps → Startup`) writes a per-entry record under `HKCU\...\Explorer\StartupApproved\Run` — first byte even = enabled, odd = disabled. A disabled entry is never started, the `Run` value looks completely healthy, and rewriting it does **not** clear the block. `autostart.blocked()` decodes it; only an explicit settings save (`sync(..., repair_block=True)`) deletes the record (no record = enabled), a startup sync merely *reports* it — an app that silently re-enables itself behind the OS switch on every launch is exactly the kind users hunt down. (2026-07-30)
- **A source checkout that lives on `PYTHONPATH` cannot autostart.** `PYTHONPATH=src python -m listen_to_me` registers `pythonw -m listen_to_me`, which the OS starts with a bare environment — the import fails and a windowed interpreter has no console to show it in, so logging in does nothing at all. `autostart.launch_problem()` probes it once per process (`subprocess` with `PYTHONPATH` stripped and cwd outside the checkout, since `-c` puts cwd on `sys.path`) and reports instead of registering a no-op; a frozen build never probes. (2026-07-30)
- **The tray icon can be dropped at logon.** An app started by the OS autostart can be up before the shell's notification area exists; `Shell_NotifyIcon` then fails, `show()` is a no-op — and Qt reports `isVisible() == True` either way, so only `QSystemTrayIcon.isSystemTrayAvailable()` tells the truth. `Tray.start()` polls it for a minute and re-adds the icon with `hide()`/`show()`. Same family of bug as the overlay watchdog. (2026-07-30)
- **A QSS variant rule silently beats a shared `:disabled` rule — and a dead button that looks live reads as "I have to click twice".** `QPushButton:disabled` and `QPushButton[accent="true"]` carry the *same* CSS specificity, so the one written later wins. With a single `:disabled { color: … }` above the variant rules, the accent and destructive buttons rendered **pixel-identically** enabled and disabled. Settings → Updates disables *Download & install* for the length of a GitHub round trip (which it starts automatically when the page opens), so the button the user reaches for first looked completely live, swallowed the click, and worked on the second press — reported as "the update and install buttons need two presses". The `:disabled` block now sits **after** every variant (which alone settles the tie) and additionally names each one, because `[accent="true"]:hover` is *more* specific than a bare `:disabled` and would bring the fill back if Qt ever reported hover on a disabled widget; `#recordBtn` outranks all of it by id. Same trap for any future `[prop="true"]` variant: pair it with its own `:disabled` (and `:focus`). Related, same family: **a button that changes label at runtime must be pinned to the widest label** (`SettingsWindow._pin_width`) — equal character counts mean nothing in a proportional font ("Checking…" is 3 px wider than "Check now"), and a control that resizes under the cursor can drop the click that is pressing it. gui_smoke's `disabled buttons look disabled` renders each variant and asserts the *surface* colour changes — a plain `!=` on the two images passed on nothing but a vanishing focus ring. **Check boxes fall into the same trap from the other direction:** the QSS rule that reserves their focus ring switches them to stylesheet rendering, and the palette's `Group.Disabled` colours stop applying — `chk_restore` (greyed out while `clipboard_copy = "always"` overrules it) rendered pixel-identically enabled and disabled until `QCheckBox:disabled, QRadioButton:disabled { color: … }` was added; the same check now renders a check box too (with the surface assertion off — it paints none). (2026-07-30, extended 2026-08-03)

## External Dependencies

- **onnx-asr (Parakeet backend) resolves models offline-first** — `load_model()` tries the HF cache with `local_files_only=True`, then downloads; but a custom `path`/local_dir that *exists* flips it to hard-offline, so an interrupted first download into `model_dir` leaves a permanently broken folder (backend raises an actionable "delete the folder" error). Parakeet TDT takes **no language/prompt/beam options** (`language`/`target_language` kwargs exist only for Whisper/Canary models); quantization maps `"fp32" → None`. ONNX Runtime providers: always append `CPUExecutionProvider` — a GPU provider that is listed but broken then degrades instead of erroring. Model files follow the `encoder-model[.int8].onnx` pattern in `istupakov/parakeet-tdt-0.6b-v3-onnx`. (2026-07-23)
- **huggingface_hub SSL opt-out is version-split** — hub **>= 1.0 is httpx-based**: `set_client_factory(...)` returning an `httpx.Client(verify=False)` (the default factory lives in `huggingface_hub.utils._http.default_client_factory`; `configure_http_backend` was **removed**). Hub < 1.0 is requests-based: `configure_http_backend(backend_factory=...)` with `Session.verify=False`. Env-var tricks (`CURL_CA_BUNDLE=""`) work with neither. `netutil.py` handles both for the `insecure_ssl` option — the v0.x-only code silently did nothing on the shipped v1.x exe. (2026-07-20)
